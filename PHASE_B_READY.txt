═══════════════════════════════════════════════════════════════════════════════
  KEY ARCHITECTURAL DECISIONS
═══════════════════════════════════════════════════════════════════════════════

1. DRY: Single shared Terraform source (Option A)
   → Dev and Prod use same code, different Terragrunt inputs
   → No duplication, consistent behavior across environments

2. Hub: Separate minimal configuration
   → Resource group + hub VNet + reserved subnets (GatewaySubnet, AzureFirewallSubnet)
   → Placeholder for future firewall/gateway integration

3. Policies: OPA/Conftest with exit code blocking
   → Checked at CI/CD stage (before terraform apply)
   → Failed policies exit 1 → GitHub check fails → merge blocked
   → No code reaches state if it violates policy

4. Protection: Removed Terraform lifecycle prevent_destroy
   → Terraform doesn't support conditional lifecycle rules with variables
   → OPA termination.rego policy enforces prod protection instead
   → Cleaner: all deletion protection in version-controlled policies
