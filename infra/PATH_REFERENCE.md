## How to Navigate (No More Backtracking!)

### From Repository Root
```bash
# Go to dev environment Terraform
cd /Users/vinodpal/Applications/aidevops/azureservicebus/infra/terraform/envs/azure-dev

# Go to dev Terragrunt config
cd /Users/vinodpal/Applications/aidevops/azureservicebus/infra/terragrunt/envs/dev
```

### From Anywhere - Using env variable
```bash
# Set once in your shell profile
export ASB_REPO="/Users/vinodpal/Applications/aidevops/azureservicebus"

# Now navigate easily from anywhere
cd $ASB_REPO/infra/terraform/envs/azure-dev
cd $ASB_REPO/infra/terragrunt/envs/dev
cd $ASB_REPO/infra/terraform/modules/network
```

### Terragrunt Absolute Paths (Computed)
In any Terragrunt file, these paths are automatically computed:
```hcl
repo_root  = dirname(find_in_parent_folders(".terragrunt-root"))
# Result: /Users/vinodpal/Applications/aidevops/azureservicebus

terraform_dir = "${repo_root}/infra/terraform/envs/azure-dev"
# Result: /Users/vinodpal/Applications/aidevops/azureservicebus/infra/terraform/envs/azure-dev

modules_dir = "${repo_root}/infra/terraform/modules"
# Result: /Users/vinodpal/Applications/aidevops/azureservicebus/infra/terraform/modules
```

## Using the Setup

### Recommended: Terragrunt (Backend + Provider Injection)
```bash
# ONLY run terragrunt from terragrunt/envs/ directory
cd /Users/vinodpal/Applications/aidevops/azureservicebus/infra/terragrunt/envs/dev

terragrunt init
terragrunt plan
terragrunt apply

# Check configuration
terragrunt validate
```

### Alternative: Direct Terraform (Pure, No Backend Injection)
```bash
# Use pure Terraform from terraform/envs/ directory
cd /Users/vinodpal/Applications/aidevops/azureservicebus/infra/terraform/envs/azure-dev

terraform init
terraform plan
terraform apply
```

### Important: Path Rules
✓ **DO** run terragrunt from: `/infra/terragrunt/envs/{dev,prod,hub}/`
✗ **DO NOT** run terragrunt from: `/infra/terraform/envs/azure-{dev,prod,hub}/`
✗ **DO NOT** add terragrunt.hcl to terraform directories
✓ **Pure Terraform files** live in `/infra/terraform/` (no terragrunt.hcl)

## Key Files & Locations

### Backend Configuration
- Path: `${REPO_ROOT}/infra/terragrunt/envs/<env>/backend_override.tf`
- Generated by: Terragrunt generate block
- Workspace: HCP Terraform `<env>` workspace

### Provider Configuration
- Path: `${REPO_ROOT}/infra/terragrunt/root.hcl`
- Contains: Azure provider features and Azure AD provider configuration
- Used by: All Terragrunt leaves and Terraform runs

### Module Sources
- Path: `${REPO_ROOT}/infra/terraform/modules/<name>/`
- Referenced from: `${REPO_ROOT}/infra/terraform/envs/*/main.tf`
- Relative path in code: `../../modules/<name>`

## No More "Module Not Found" Errors!

The setup is designed so that:
1. **Relative paths work** when running Terraform directly from the envs/ directory
2. **Absolute paths are computed** by Terragrunt for configuration and documentation
3. **All paths resolve correctly** whether you're in the repo root, infra/, or any env directory

If you get path errors:
- Ensure you're running `terraform init` from the correct directory
- Check that you're in `/Users/vinodpal/Applications/aidevops/azureservicebus/infra/terraform/envs/<env>/`
- Verify the `.terragrunt-root` marker file exists in the repo root
